**24C stage 1 (co-op networking base) is merged to `main`**, code in this same push (branch `agent/coop-net`, verified on its own clean worktree rebased onto current `main`: `--import` clean, `---- 120 test files, 0 failed, 249.6 s ----`, `RESULT: PASS`).

- **Transport (`scripts/net/coop_session.gd`):** ENet through `SceneMultiplayer` with raw `send_bytes` packets (no RPC), 4 channels. The host opens a lobby for 2 to 4 peers; joiners connect by `ip`, `ip:port` or a code like `ABCD-EFGH-IJKL` (base32 of IPv4, port and a check byte). Heartbeats and timeouts, graceful BYE, kick, host-closed message. A dropped client retries every 2 s for 60 s with its token and gets the same seat and a fresh snapshot; the host holds the seat 60 s and replays the cached ack for any order already applied.
- **Protocol (`coop_proto.gd`):** 16 message types with schemas and size caps; one Dictionary per packet through `bytes_to_var` (never the objects variant); rejects unknown types, missing or extra fields, wrong kinds, NaN/inf, nested objects, depth over 3, oversize and truncated packets; per-peer rate limit 30/s burst 60, sustained flood or 20 bad packets removes the peer. The handshake refuses a protocol or game-build mismatch in plain words, naming both versions; other plain-language refusals: lobby full, can't reach the host (UDP port-forwarding hint), host left, removed by host.
- **Snapshot:** `SaveLoad.snapshot()` to JSON to zstd to 32 KB chunks with an MD5 checksum; the reassembler copes with reordering, duplicates, stale transfers, corruption and truncation; the client restores in memory (save slots untouched) and reports its hash; the host answers SYNC ok or fail, the client re-requests up to twice; progress shows in the lobby.
- **State hash (`CoopHash.of_world()`):** 16 hex chars of SHA-256 over clock minute, `Folk._next_id`, each household folk's id, tile, level, household and needs (quantised), coins per household, world object count; deterministic across two fresh loads and equal to the host's hash. Crowd and visitor NPCs are excluded (not restored from a snapshot).
- **Commands:** envelope `{player_id, folk_id, action, args, game_minute, seq}`; client re-sends every 2 s up to 6 times until acked; the host rejects a `player_id` that isn't the sender's, applies each seq once and answers repeats from a cache, and publishes an EVENT `command` to everyone. One thin adapter, `CoopCommands.apply()` / `_sim_director()` in `scripts/net/coop_commands.gd`, calls today's `SimDirector.command`.
- **UI:** `scripts/ui/coop_lobby.gd` with Host and Join tabs (code and address, NAT note, player list with ready or "away, can rejoin", Remove; progress bar and "Refresh town from the host"). The only shared edit: a "Co-op" button on the title menu (`title_menu.gd`, +11 lines).
- **Tests:** `coop_proto_test`, `coop_reassembler_test`, `coop_host_test` (in-memory: handshake, version and build refusal, the 4-peer limit, heartbeat timeouts, reconnect and takeover, garbage and flood handling, command idempotence and lost-ack re-send, kick and close), `coop_hash_test`, `coop_commands_test`, `coop_lobby_test`, and `coop_net_test` over real localhost sockets on a random free port with a second headless Godot client under the guard with `--budget` (joins, receives the snapshot with the same hash, sends a command, the host's authoritative state changes and the client gets the result event, 20 more host minutes then a fresh snapshot matches again, the client process is killed and a new one rejoins with the token: same seat, no ghost, same hash; a mismatching build is refused).

**Rough edges:** IPv4 only; no NAT punch or relay (the host forwards UDP, or both use a VPN; `CoopAddress.resolve_hook` is the extension point); the code encodes the LAN IP only; in stage 1 the client is a frozen view refreshed on request and the lobby can't send orders yet (only the protocol and the test fixture do); mid-interaction state isn't in the snapshot so the hash excludes it; `coop_net_test` takes about 20 s because it starts a second Godot.
